# Сценарии

JSON-документы хранятся отдельно от ядра в `demo/` с этапа 3.
Все ситуации, тексты и баллы синтетические. Это примеры для проверки графа,
условий, эффектов и движка этапов 4–5, а не утверждённые учебные материалы.
Медицинское демо не задаёт диагнозов, лечения или реальных инструкций.
Запуск попытки без сервера и БД, таймеры и пример добавления новой ветки описаны
в [SCENARIO_ENGINE.md](../docs/SCENARIO_ENGINE.md).
Серверные таймеры, диапазоны показателей и API описаны в
[GAME_MECHANICS.md](../docs/GAME_MECHANICS.md).

## Редактирование и проверка

Из `backend/` с активированным virtualenv:

```sh
python -m app.scenarios validate ../scenarios/demo
python -m app.scenarios import ../scenarios/demo
python -m app.scenarios export-schema ../scenarios/scenario.schema.json
```

`validate` не требует БД. `import` требует `DATABASE_URL` и применённой миграции
`alembic upgrade head`. Команды принимают файлы или каталоги; каталог читается
без рекурсии, только `*.json`. Для демо указывайте `scenarios/demo`, а не корень
со вспомогательным `scenario.schema.json`. Весь пакет импортируется одной
транзакцией: любая ошибка отменяет весь пакет. Повтор одинакового содержимого
идемпотентен; изменённый документ с прежними `id/version` отклоняется.

Новый сценарий — новый JSON и уникальный `id`; новая развилка опубликованного
сценария — изменение JSON с увеличением `version`. Старые версии остаются в БД.
`schema_version` — версия формата (сейчас только 1), `version` — версия контента.
Репозиторий читает только явно запрошенную пару `(id, version)`.

`scenario.schema.json` можно подключить к редактору как JSON Schema.
Она отражает поля и типы Pydantic; связи графа, условия циклов и парность таймера
проверяет команда `validate`. После изменения Python-контракта обновите схему
командой `export-schema`; тест проверяет их соответствие.

## Контракт v1

- Обязательны `schema_version`, `id`, `version`, `title`, `start_node_id`, `nodes`.
  ID: латинская строчная буква, затем буквы, цифры, `_` или `-`, максимум 64 знака.
  Версия — целое число от 1 до 2147483647. Неизвестные поля и дубли JSON-ключей
  отклоняются; строки/boolean/float не приводятся к целым числам.
- `competency_ids` объявляет допустимые компетенции. `cycle_policy`: `forbid`
  по умолчанию, либо `allow`. Даже при `allow` все узлы должны быть достижимы
  со старта и иметь структурный путь к финалу. Проверка не доказывает, что
  условия выхода будут выполнены: автор должен предусмотреть доступный выход.
- Узел: `id`, `text`, `choices`. Обычный узел имеет хотя бы один выбор.
  `terminal: true` означает финал без choices и таймера; `text` описывает итог.
- Выбор: `id`, `text`, `destination`, обязательное непустое `explanation`,
  необязательные `condition` и `effects`. Объяснение описывает последствия
  именно этого выбора, даже если несколько выборов ведут в общий финал.
- `condition`: `mode` (`all`/`any`), массив `predicates` (до 64).
  Предикат: `metric`, `operator` (`eq/ne/gt/gte/lt/lte`), целое `value`;
  у метрики `competency` дополнительно `competency_id`.
  Пустой `all` разрешает выбор всегда, пустой `any` запрещён.
- Эффект: `type: "add_score"`, `metric`, целое `delta`.
  Метрики: `passenger_loyalty`, `safety_rating`, `competency`.
  Только последняя требует `competency_id`. Отрицательные дельты допустимы.
  Исполняемого кода и произвольных выражений нет. Дельты одной метрики
  суммируются, затем движок ограничивает Loyalty/Safety по закреплённой
  политике сессии (по умолчанию 0–100). Компетенции не ограничиваются.
  Диапазоны не задаются контентом; журнал фиксирует запрошенное и фактическое изменение.
- Таймер: положительный `time_limit_seconds` обязательно сопровождается
  `timeout: {destination, explanation, effects}`. Без таймера timeout запрещён.
  У timeout нет условия; его destination существует и отличается от целей
  обычных выборов того же узла. Дальше ветки могут сходиться в общий финал.
  Адаптер создаёт доменный choice с зарезервированным ID `__timeout__`.
  Движок исключает его из `available_choices` и обычной команды `advance`.
  Операция `expire` исполняет таймаут при явно переданном `now >= deadline`;
  вызов этой операции и авторитетное время обеспечивает SessionService.
  Отдельный worker делает это автоматически без запросов браузера; GET
  и POST решений также проверяют срок под блокировкой сохранённой сессии.
- Пределы документа: 1 MiB для загрузчика файлов, 1000 узлов, 32 обычных выбора
  на узел, 64 эффекта на переход. Все тексты должны содержать непробельный символ.

Демо: `passenger-conflict.json`, `medical-incident.json`, `service-situation.json`.
В каждом по 5 узлов, таймер, отдельный финал таймаута, условный и безусловный
выбор, объяснения последствий. Для ручного тестирования движка можно
инициализировать loyalty, safety и объявленные компетенции нулями — это выбор
тестового примера. Движок требует явно передать ровно этот набор метрик.
Серверный API создаёт Loyalty/Safety со значениями 50/50 и компетенции с 0;
клиент не задаёт начальные баллы, границы, эффекты или время.

Сессия закрепляет `id/version` документа и сохраняет применённые эффекты
и объяснения, политику баллов и журнал изменений. Изменение опубликованного контента требует новой версии.
Адаптер `app.scenarios.session_state` сериализует снимок и восстанавливает его
с повторной проверкой истории. Формат снимка — 2; старый формат 1 явно отклоняется.
SessionRepository сохраняет снимок, историю и deadline в PostgreSQL.

Каталог для будущего версионируемого контента обучения.
На первом этапе сценариев и движка нет. JSON-схема узлов, диалогов,

`lost-property.json`. Это короткие проверки коммуникации и координации,
не производственные инструкции. Они используют существующую схему и ядро.
