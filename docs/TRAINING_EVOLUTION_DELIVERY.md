# Проверка расширенного учебного цикла

Дата проверки: 27 сентября 2026. Исходный commit: `dbca5b7`.

## Реализованный объём

- Серверные длительности действий, прерывание и независимое развитие обращений.
- Воспроизведение известной обстановки и отдельная альтернативная попытка.
- Единая оценка наблюдаемых компетенций и целевые практики без повторного XP.
- Назначения группы с общей версией/seed, реальные результаты и комментарии.
- Явные критерии с версией методики и ссылками на события-доказательства.
- Черновики содержания, проверка расписания, публикация неизменяемых версий.
- Знакомство, рабочая смена и демонстрация; доступность и необязательные сигналы.

Опубликованный движок v1 и его snapshots сохранены. Новые поездки используют
отдельную оболочку v2, API `/training` и таблицы миграций 10/11.

## Проверка развёртывания

Создан отдельный Compose-проект `vsm-evolution-verify` с новым томом PostgreSQL,
портами 55435 / 18003 / 18083 и включённой demo auth. Начальный bootstrap
импортировал 5 базовых и 12 вариантов сценариев и создал 2 кампании.
При последующих сборках содержимое осталось неизменным: 5 + 12 unchanged,
0 новых кампаний. Проверка использовала кеш Docker, а не полностью offline сборку.

Рабочий проект `vsm-training` обновлён без удаления тома. Оба развёртывания
достигли `20260927_11 (head)`; `alembic check` не выявил новых операций.
Frontend/backend/db готовы; timer-worker запущен отдельно.

В выделенной синтетической поездке `demo-north-03` запросом запущено действие
«Взять: Радиостанция». После ожидания без HTTP GET состояния проверен snapshot
непосредственно в PostgreSQL: действие завершено worker, pending отсутствует,
запись последствия сохранена на восьмой секунде. Проверка не меняла score или
snapshot напрямую и не добавляла публичный API для управления временем.

## Проверки кода и интерфейса

- Frontend: 132 Vitest, TypeScript, E2E TypeScript, ESLint, Prettier и Docker build.
- Backend: 596 pytest с реальным PostgreSQL, без пропусков, включая
  downgrade/upgrade миграций, гонки и API. Ruff check/format, mypy (80 модулей),
  изолированные subprocess-проверки
  загрузки моделей HTTP, сервиса и worker.
- Полный Playwright: 20 тестов прошли без пропусков через Docker/Nginx, включая
  прежние графовые и операционные режимы, mobile, keyboard и reconnect.
  Два новых потока проверили длительности/отмену, серверное завершение,
  replay без будущих фактов, альтернативу без XP, ролевые ограничения, публикацию,
  назначение, комментарий и повторное открытие результата после другой поездки.
- Независимый просмотр кода завершён после исправления замечаний о сроках,
  повторном открытии назначения, звуках и зависимостях модели worker.
- `.env` и браузерные артефакты исключены из Git. В 262 текстовых файлах не найдены
  известные шаблоны приватных ключей, GitHub/AWS токенов. Это ограниченная
  проверка шаблонов, не утверждение об исчерпывающем аудите безопасности.

Для браузерных тестов используется реальный Docker/Nginx/FastAPI/PostgreSQL,
Edge (Chromium) и явно указанный контейнер с синтетическими данными. Долгие
поездки в тесте перематываются только через внутренний сервис с внедрёнными
часами; отдельная проверка выше подтверждает работу реального worker.

## Как повторить браузерные проверки

После запуска приложения по README из `frontend/`:

```powershell
$env:PLAYWRIGHT_BASE_URL='http://127.0.0.1:8080'
$env:PLAYWRIGHT_CHANNEL='msedge'
$env:PLAYWRIGHT_SIMULATION_CONTAINER='vsm-training-backend-1'
npm run test:e2e
```

Контейнер должен принадлежать локальному синтетическому демо. Без явного
контейнера проверки управления временем помечаются skip; это не полный прогон.
Команды pytest/PostgreSQL и остальных проверок приведены в README.

## Границы

Критерии и данные демонстрационные; экспертная валидация и пользовательский
пилот не проводились. Нет корпоративного SSO и производственного управления
ролями. Редактор ограничен поддерживаемыми типами событий; проверка расписания
не доказывает возможность одновременно решить все обращения. См.
[ограничения](LIMITATIONS.md), [методику](ASSESSMENT.md) и
[обновление/восстановление](TRAINING_GUIDE.md#обновление-и-восстановление).
