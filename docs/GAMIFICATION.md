# Прогресс проводника — этап 8

## Назначение и принятые решения

Замкнутый цикл: завершить ситуацию → получить объяснимую награду → увидеть
рост уровня и компетенций → открыть достижение → сравнить результаты своего
подразделения → начать следующую ситуацию. Сохраняется визуальный язык смены:
личный учебный паспорт, линейный журнал достижений и табло рейтинга без сетки карточек.

Источник — проверенные сервером завершённые сессии. Журнал наград с уникальным
session_id сохраняется в той же транзакции, что финальное решение/таймаут.
Блокировка профиля `FOR NO KEY UPDATE` сериализует начисления разных сессий
одного проводника, совместима с FK-блокировкой идемпотентного старта.
Повтор HTTP, refresh, worker и конкурентное завершение не удваивают XP/unlock.
Старые завершённые попытки учитываются при первом чтении прогресса; они проходят
такую же проверку снимка. Активные попытки наград не дают.

## Правила v1

- Без действий пользователя (только timeout или сразу терминальный старт):
  0 XP и 0 очков компетенций.
- Иначе за завершение: 20 XP; за положительный суммарный прирост loyalty/safety:
  5 XP за балл, максимум 50; за положительный итоговый прирост компетенций:
  10 XP за балл, максимум 30; за успешные критические решения: 10 XP, максимум 30.
- Компетенции: положительный итоговый прирост каждой компетенции за попытку.
  Начальные очки не начисляются повторно; отрицательные итоги не уменьшают
  накопленный учебный прогресс. Полный отрицательный результат остаётся в разборе.
- Порог уровня L: `50 * L * (L - 1)` XP. Уровень 1 начинается с 0, уровень 2 —
  со 100, уровень 3 — с 300. XP не тратится и не меняет safety/loyalty сессии.
- Новая попытка даёт новую награду; повтор запроса существующей — нет. Это правила
  учебного демо, не production-защита от многократного прохождения одного задания.

Поведенческие достижения (без бонусного XP, чтобы избежать рекурсивного начисления):

1. «Надёжная смена»: 3 завершения с safety ≥ 50, без снижения safety на любом
   решении и без timeout. Прогресс — число подходящих попыток из 3.
2. «Общий язык»: конфликт `demo-passenger-conflict` v1 завершён в `resolved`,
   без снижения loyalty на любом шаге и без timeout. Правило относится к этой
   версии учебного контента, ядро движка о нём не знает.
3. «Точно в срок»: 3 успешных критических решения подряд. Критическое решение
   успешно, если принято вовремя и не снизило safety. Timeout или небезопасный
   критический выбор сбрасывает серию. Некритические решения её не меняют.
4. «Мастер диалога»: накопить 3 очка communication.

Серия считается по порядку начисления завершённых попыток, внутри попытки —
по порядку решений. Unlock необратим: сохраняются версия правила, время и
сессия-основание. После открытия progress фиксируется на цели.

## Подразделения и рейтинг

Принадлежность компании/депо/бригаде задаёт сервер. Для demo доступны несколько
синтетических персон с фиксированной принадлежностью и пустым начальным прогрессом.
Они не представляют реальных работников. Без выбора сохраняется demo-employee.
Выбор demo-персоны доступен только при включённом DEMO_AUTH_ENABLED.

Рейтинги показывают проводников с завершёнными попытками в той же бригаде, депо
или компании. Бригада проверяется вместе с депо и компанией; депо — с компанией.
Сортировка по накопленному XP, равные XP дают одинаковое место (1, 1, 3), ID
стабилизирует порядок. Пагинация не меняет глобальное место. Выдуманные результаты
и строки для заполнения таблицы не создаются. Старый рейтинг по сценарию сохранён.

## Реализация и проверки

1. `app/domain/gamification.py`: чистые правила награды, уровня и прогресса;
   unit-тесты границ, нулевого результата, штрафов, сброса серии и открытия.
2. `app/persistence/gamification.py`, миграция 04, application service:
   единственное начисление, сериализация профиля, backfill, сохранённые unlock.
   PostgreSQL-тесты повторов, параллельных завершений и терминальных стартов,
   worker и rollback.
3. REST schemas и тонкие routes прогресса, награды, персон и рейтинга;
   проверка доступа, групп, пагинации и расчёта на реальных результатах.
4. Учебный паспорт и табло в React; награда в разборе, переключение demo-персоны
   вне активной попытки, loading/error/retry, клавиатура и reduced motion.
5. Все тесты, lint/typecheck/format/build, миграции и Docker, browser E2E;
   просмотр diff, `feat: add conductor gamification system`, push и остановка.

Маршруты: `GET /api/v1/profiles/me/progress`,
`GET /api/v1/leaderboard/organization`, `GET /api/v1/auth/demo/personas`.
Контракты и выбор персоны — в [API.md](API.md). Команды запуска и проверок —
в [README](../README.md). Backend-тесты выполняются в изолированных схемах
PostgreSQL; браузерные проверки добавляют синтетические прохождения в локальную БД.

После завершения экран разбора показывает серверную награду, прирост компетенций
и новые достижения. «Мой прогресс» открывает паспорт, «Рейтинг» — табло подразделения.
Смена учебной персоны доступна в паспорте вне активной попытки. При ошибке чтения
можно повторить запрос; переключение персоны отменяет прежние запросы, обновление
истёкшего токена сохраняет выбор. Браузер не вычисляет XP и не хранит итоговые очки.

Этап 9 дополняет паспорт аналитикой компетенций и обучающим разбором. Накопленные
положительные очки здесь сохраняются; отрицательные результаты и нейтральные
наблюдения отдельно видны в аналитике. Правила XP и unlock не меняются.
Подробнее — [DEBRIEF_ANALYTICS.md](DEBRIEF_ANALYTICS.md).

## Границы

Правила демо требуют продуктовой балансировки. Production SSO, управление
организацией, антифрод и HR/LMS не добавляются. Для небольшого каталога агрегаты
считаются из журнала наград при чтении; отдельные аналитические проекции потребуются
при росте объёма. Клиент не может назначить XP, достижения или подразделение.
