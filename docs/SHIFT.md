# Рабочая смена — учебный маршрут

Смена объединяет три серверные сессии: сервис → конфликт → нештатная ситуация → итог. Это тренировочная модель, не подтверждение допуска к работе и не нормативная инструкция. Старые демонстрационные сценарии и их версии не изменены.

## Воспроизводимый маршрут

Чистый планировщик `app/domain/shifts.py` получает seed (целое 0…2147483647) и standard/advanced. Сервер создаёт seed и сохраняет его с route_version=1, сложностью и полным планом. Два опубликованных варианта каждого типа дают восемь сочетаний на сложность: семья/пересадка, шум/место, проход/сигнал. Пассажир, контекст и заголовок закреплены за вариантом.

В `scenarios/shifts` находятся 12 документов: шесть новых сценариев × версии 1 и 2. Стандартная версия имеет оценку, проверку, эскалацию, восстановление после таймаута и разные исходы. В сложной версии первичный срок сокращён с 60 до 25 секунд; успешная проверка открывает дополнительное событие со сроком 20 секунд. Решения меняют безопасность, сервис, регламент и коммуникацию. Условие регламента проверяет существующий движок. LLM во время игры не используется.

После публикации `SHIFT_VARIANTS`, порядок типов и алгоритм route_version=1 сохраняются неизменными. Новый алгоритм требует новой версии маршрута. Ссылки на сценарии содержат точный номер опубликованной версии.

## Хранение и транзакции

Миграция `20260926_07` после `20260926_06` добавляет:

- `training_shifts`: владелец, ключ старта, seed, версия, сложность, состояние, время и окончательный итог.
- `shift_steps`: план и ссылки на опубликованный сценарий и созданную сессию.
- `shift_commands`: принятые переходы с ожидаемым этапом, сессией, результатом и серверным временем.
- `shift_achievements`: постоянные учебные достижения с первой сменой-основанием и временем выдачи.

Разрешена одна активная смена на владельца; частичный уникальный индекс защищает правило при конкуренции. Старт сериализуется блокировкой профиля. Переход блокирует смену и текущую сессию, выдача достижения — профиль. Повтор старта освобождает профиль перед чтением существующей смены, чтобы не инвертировать порядок блокировок завершения сессии.

Сначала создаётся только первая сессия. Следующая появляется атомарно с квитанцией перехода, только после завершения текущей. Чужая сессия, пропуск этапа и незавершённый этап отклоняются. Ошибка создания/расчёта/аудита откатывает транзакцию. БД требует для completed индекс3, непустое время завершения и JSON-объект итога.

Повтор ключа старта с прежней сложностью возвращает смену, с другой —409. Повтор принятого command_id с теми же expected_step/session_id возвращает актуальное состояние; другие аргументы —409. Квитанции PostgreSQL работают после перезапуска и для нескольких процессов. После потери ответа клиент читает `/shifts/current` и обычную сессию.

GET сверяет план с seed/версией и восстанавливает связанные сессии существующим движком. Просроченное решение обрабатывается через SessionService; таймаут сохраняется, даже если advance затем возвращает409 из-за активного восстановления. GET не переключает этап. Завершённый итог сверяется с пересчитанными сессиями.

## Метрики и XP

Этапы используют начальные показатели отдельных обычных сессий; состояние между сценариями не переносится.

| Поле                      | Определение                                                                                                                                                                                                       |
| ------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| safety, service           | Среднее показателей безопасности и лояльности по начатым этапам; после завершения — по всем трём.                                                                                                                 |
| regulation, communication | Сумма фактических изменений компетенции относительно начала каждого этапа.                                                                                                                                        |
| average_reaction_seconds  | Среднее серверное время от входа в узел до принятого решения пользователя; автоматические таймауты исключены. Null при отсутствии решений пользователя. Включает сеть и время вне вкладки, не только размышление. |
| decision_count            | Все подтверждённые переходы, включая автоматические таймауты.                                                                                                                                                     |
| critical_errors           | Решения на узле с ограничением времени, где был таймаут или фактическое снижение безопасности; один переход считается один раз.                                                                                   |
| completed_scenarios       | Число завершённых связанных сессий; total_scenarios всегда3.                                                                                                                                                      |
| xp                        | Сумма уже существующих SessionReward.xp связанных сессий.                                                                                                                                                         |

Смена не начисляет дополнительный XP. Расчёт и дедупликация остаются в существующем завершении сессии. Детальный разбор этапов доступен через прежний debrief API. Рекомендации по смене детерминированно выводятся из показателей.

## Постоянные учебные достижения

Все требуют завершения трёх этапов; запись уникальна по владельцу и ID. API показывает пожизненные разблокировки, включая предыдущие смены. Это учебные отметки, не кадровые квалификации; сами достижения XP не начисляют.

| ID               | Критерий                                                                                                                                                                                           |
| ---------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| shift-safe       | Нет критических ошибок, безопасность не ниже60.                                                                                                                                                    |
| shift-regulation | Положительный прирост регламента каждого этапа без решений с его снижением.                                                                                                                        |
| shift-conflict   | На конфликтном этапе прирост коммуникации≥2, нет решений со снижением сервиса.                                                                                                                     |
| shift-response   | Все решения за1–15секунд, нет отрицательных фактических эффектов и критических ошибок. Правило тренажёра, не доказательство отсутствия автоматизации.                                              |
| shift-advanced   | Сложная смена без критических ошибок; название «Подготовка: сложная смена».                                                                                                                        |
| shift-growth     | В непосредственно предыдущей завершённой смене регламент или коммуникация отрицательны, а в текущей тот же навык положителен. Нулевой/положительный прежний результат не считается слабым навыком. |
| shift-steady     | Три последовательные завершённые смены без критических ошибок, безопасность каждой≥50. Незавершённая смена прогресс не даёт.                                                                       |

Предыдущие смены сортируются по completed_at, затем id; текущая явно включается первой. Итог и достижения сохраняются атомарно с финальной квитанцией.

## HTTP-контракт

Все маршруты требуют авторизацию. Владелец берётся из токена; клиентские seed, результаты, время, XP и employee_id не принимаются. Лишние поля запросов запрещены.

- `POST /api/v1/shifts`, заголовок Idempotency-Key, тело `{"difficulty":"standard"}` либо advanced (по умолчанию standard). 201 создание, 200 повтор, 409 другая активная смена/конфликт ключа.
- `GET /api/v1/shifts/current` → `{"shift": ShiftResponse|null}`. Текущая либо последняя завершённая смена; null только при отсутствии смен.
- `GET /api/v1/shifts/{id}` → ShiftResponse; чужая/отсутствующая смена —404.
- `POST /api/v1/shifts/{id}/advance`, тело `{"command_id":"…","expected_step":0,"session_id":"…"}` → ShiftResponse. expected_step целое0…2. Неготовый/неверный этап или конфликт ID —409.

ShiftResponse: `id,title,status,seed,difficulty,started_at,completed_at,current_step,current_session_id,steps,metrics,achievements,recommendations`. status=active/completed; завершённая смена имеет current_step=3 и current_session_id=null. Этап: `index,kind,title,scenario_id,scenario_version,passenger_profile,context,session_id,status`; kind=service/conflict/critical, status=locked/active/completed. Достижение: `id,title,description,unlocked`.

Решения принимает прежний session API. Общий authenticated-command middleware ограничивает shift_start/shift_advance. Начало этапа, повторы и финальное завершение пишут аудит в той же транзакции; финальный аудит содержит xp_granted=0. API-ошибки используют проверенные метаданные, без исходных тел.

## Проверка и запуск

`tests/domain/test_shifts.py`: воспроизводимость seed, 12 документов и ветвление, сложность, метрики, исключение таймаута из реакции, достижения. `tests/timed_sessions/test_shift_routes.py` на реальном PostgreSQL: авторизация/подмена, порядок этапов, идемпотентность, конкуренция, перезапуск, откат, таймаут, XP, постоянные достижения/рост/серия, аудит и ограничения завершённого состояния.

Контент импортируется существующим bootstrap через ScenarioRepository из `scenarios/shifts`. Миграции и импорт завершаются до открытия смен пользователям.
