# Аналитика: действующие правила и граница нового scope

Этот файл добавлен как входная точка после сверки требований встречи.
В исходном учебном продукте отдельного `docs/ANALYTICS.md` не было:
правила, контракты и ограничения уже описаны в документах ниже.

- [DEBRIEF_ANALYTICS.md](DEBRIEF_ANALYTICS.md) — основной документ этапа 9:
  разбор, наблюдения компетенций, достаточность данных, динамика, паттерны
  и статистика сценариев.
- [API.md](API.md#обучающий-разбор-и-аналитика--этап-9) — маршруты
  `/sessions/{session_id}/debrief` и `/analytics/me/competencies`, ownership
  и read models; прежний `/analytics/me` сохраняет свой смысл.
- [ARCHITECTURE.md](ARCHITECTURE.md#этап-9-обучающий-разбор-и-аналитика-компетенций)
  — вычисление из проверенной истории по закреплённой версии сценария.
- [GAMIFICATION.md](GAMIFICATION.md) — XP, накопленный прогресс и журнал наград.
- [RETENTION.md](RETENTION.md) — учебные challenges и внутренние уведомления.
- [LIMITATIONS.md](LIMITATIONS.md) — методические ограничения и масштаб демо.

Сейчас аналитика относится к решениям **проводника в синтетических сценариях**.
Сервер формирует выводы, React отображает их. Активные попытки учитываются
в статистике попыток, но не доказывают сильную или слабую компетенцию.
Недостаточность наблюдений не означает слабость и не удостоверяет квалификацию.

## Пассажирская аналитика пока не определена

Новая постановка и открытые вопросы находятся в
[MEETUP_ALIGNMENT.md](MEETUP_ALIGNMENT.md). Поездки, покупки, питание,
пассажирские достижения и ценная бонусная валюта требуют собственных источников
истины, определений метрик, прав доступа, временных правил и правил коррекции.
Данные локального PendingClientEvent нельзя включать в подтверждённые награды
только по факту отправки клиентом.

| Учебная величина             | Чему она не эквивалентна                                        |
| ---------------------------- | --------------------------------------------------------------- |
| `passenger_loyalty`          | Балансу пассажирских бонусов или оценке реального пассажира     |
| `safety_rating`, компетенции | Статусу реальной поездки или производственной аттестации        |
| XP и earned_points           | Расходуемой валюте, сумме покупок или денежному обязательству   |
| Завершение сценария          | Подтверждённому TripCompleted                                   |
| Deadline учебного решения    | Фактическому времени прибытия поезда                            |
| Учебный challenge            | Утверждённому месячному или коллективному пассажирскому заданию |

Общий event/ledger-прототип не меняет эти метрики и не подключён к действующим
read models. Его последовательные receipts не создают готовую пассажирскую
аналитику. Для будущих метрик потребуется отдельно определить occurred_at,
received_at, допустимую задержку, переупорядочивание, отмены и исправления фактов;
правила и формулы до подтверждения scope не выбираются.

## Учебный сервис: дополнение текущего этапа

Личная аналитика дополнена недельными агрегатами по completed_at (UTC, начало
недели — понедельник), лучшими фактическими конечными шкалами и средним временем
принятых решений. Автоматические timeout не входят во время реакции. На графике
компетенции показаны реальные накопленные очки, а недостаток данных обозначен.

Разбор каждого события содержит локальную оценку последствия: сильное решение,
нейтральное, требует внимания или критическая ошибка. Это детерминированные
эвристики на основании доступных вариантов и журнала эффектов, не утверждение
единственно правильного поведения в реальной эксплуатации.

Сводка **полной смены** отдельно агрегирует три связанные попытки;
[SHIFT](SHIFT.md). Обзор команды не добавлен без утверждённой роли администратора.
Аномалии сохраняются в техническом аудите, [ANTI_CHEAT](ANTI_CHEAT.md).
